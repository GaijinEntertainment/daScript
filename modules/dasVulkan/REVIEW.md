# dasVulkan Code Review Checklist

**Read `REVIEW_COMMON.md` (repo root) first — its contract binds this checklist.** Architecture doc:
`CLAUDE.md`. Planned work: `ROADMAP.md`.

**A new or renamed `daslib/*.das` file lands both of its registration points in the same change** —
an `ADD_MODULE_DAS(vulkan daslib <name>)` line in `CMakeLists.txt` and a `register_native_path`
entry in `.das_module`. One without the other resolves in only one build flavor.

**Generated sources are never hand-edited — change `generator/` and regenerate instead.** A diff
touching any `src/dasVULKAN.gen*` file, or any `daslib/*.das` whose first line reads
`// generated by generator/generate.das -- DO NOT EDIT`, with no accompanying `generator/` change
is a defect.

**A diff that grows `generator/skip_report.txt` states in its commit message why the newly skipped
surface is acceptable.** CI checks only that the committed report matches a fresh run; whether
losing that bound surface is intended is the reviewer's call.

**A new public function in `daslib/vulkan_boost.das` or `daslib/vulkan_window.das` lands its
`utils/vulkan2rst.das` group entry in the same change**, plus an anchor on the stdlib
external-types page for every type it exposes that no documented boost module defines. Missing the
group entry leaves the function undocumented; missing the anchor dangles the generated page's
reference and fails the `-W` docs build.

**A tutorial that renders ships `tutorials/<NN_name>/window/show_<name>.das`** — a real GLFW window
presenting the live animation. The offscreen pixel-oracle test proves correctness; nothing else
lets a human see the result.
