Keeps the function out of best-effort (automatic) inlining: block-literal call-site splicing and the heuristic plain-call tier (options auto_inline_functions) both skip it. Combining it with [inline] is a compile-time error - the two contracts are contradictory. The same annotation on a block literal keeps that block from invoke-block inlining. Module-wide, options never_inline takes every function the module defines (instances of its generics included) out of inlining entirely - [inline] calls to them degrade to plain calls.
